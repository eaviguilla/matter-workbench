# Matter Workbench

Start with `docs/ARCHITECTURE.md`. It is the full guide for a new agent (purpose, data model, flows, routes, decisions, open items). This file holds the working rules and the per-round notes. Older bullets may still mention the global Keep first names setting, the sidebar Add a client box, or a Delete button on Hidden names (now Unscrub). Those were changed, see section 14 of the architecture file.

Local scrubber and rehydrator for call transcripts. Spec: the "Transcript Workbench - Build Spec" artifact. All build-spec milestones are done: scrubber, GLiNER stage, storage, web app (`app/web`, `app/workflow.py`), security tests, design pass, README, plus the optional connector (`mcp_server`), summary helper and Markdown export. The real model is installed in `models/gliner_pii` (gitignored); tests that need it skip if it is missing. Run the app with `python -m app` or `python -m app --demo`.

## Commands

Run tests with the project venv. Create it once.

macOS or Linux:

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

Windows PowerShell:

```powershell
py -3 -m venv .venv; .venv\Scripts\pip install -e ".[dev]"
```

Then run the tests.

macOS or Linux:

```bash
.venv/bin/python -m pytest
.venv/bin/python scripts/eval_scrub.py --show 1
.venv/bin/python scripts/eval_scrub.py --model-dir models/gliner_pii
```

Windows PowerShell:

```powershell
.venv\Scripts\python -m pytest
.venv\Scripts\python scripts\eval_scrub.py --show 1
.venv\Scripts\python scripts\eval_scrub.py --model-dir models\gliner_pii
```

## Rules

- Fixtures are synthetic only. Never commit real transcripts. Ground truth lives inline in `tests/fixtures/*.ann.txt` as `{P1:Name}`, `{E1:email}`, `{A1:address}`.
- The real-model save test (`tests/test_real_model_save.py`) must stay green, because the other web tests use a fake model. A flag must cover a whole word, or a Scrub decision can never clear it.
- A miss is a leak. Recall is the target metric; over-scrubbing only costs readability.
- No network calls, no logging of transcript text.
- Python 3.11+. Runtime dependencies are in pyproject (fastapi, uvicorn, jinja2, python-multipart; the `ner` extra for the model).
- A new transcript starts at `/intake` with no client chosen. `workflow.detect_client` scrubs against an empty registry and guesses the client (the first speaker is treated as office staff). `POST /intake` creates the client at once unless any client matches or no name was found, and then shows `choose_client.html`. A full-name match or the same first name as an existing client stops and asks (`choose_client.html`, with the last call date and an Add to this client button); only a person no client could be creates a new client at once. Returning clients use `/clients/{cid}/intake`. Renaming changes the display name, never the ID. `Store.delete_empty_client` only deletes a client with no transcripts or messages.
- Saving the same call twice (same client, date and scrubbed text) returns the existing transcript. Archived clients are matched like active ones and restored when picked. A future call date is refused. Form posts that fail (HTTP errors, an expired CSRF token) show `error.html`; scripts sending JSON keep JSON errors.
- Transcript layout is never a reason to refuse text. `parse_lenient` (app/scrub/parse.py) reads speaker lines when it can, marks role labels as `generic` (never registered as people), and otherwise scrubs the whole text. Only an empty paste or one over the size cap is refused. `ScrubResult.notes` tells the user how the text was read. The strict `parse_transcript` is kept for its tests and as the first check.
- Packaging: `scripts/package.py` builds `dist/matter-workbench-<version>.zip` from an allow list (never a block list) and refuses to pack records or secrets. `run.py` (stdlib only) is the one entry point for users. It installs on first run into `.venv`, writes `.venv/installed.json`, and later only starts the app. Windows paths are unit-tested by simulation only. New runtime files must be added to `DIRS` or `FILES` in `package.py`, and the `--demo` mode does not work from the zip because it needs `tests/fixtures`.
- Layout is built for a full or half-width desktop window and still works down to phone width. Breakpoints are in the last block of `style.css` (1500, 1100, 960, 720, 480). Check new screens at about 800 and 390px for horizontal overflow.
- Theme: a sun or moon icon in the top bar switches Light and Dark (no auto mode; it starts from the system setting). `theme.js` (head) applies the saved choice before paint, `app.js` flips it, `style.css` keys the dark tokens on `:root[data-theme]` and the system setting.
- Screens: the word for a saved item is "Transcript" in every label (the tab, headings, selector); routes keep `/transcripts/`. One client page, `/clients/{id}`, is the working page. `?tx=` picks a transcript (newest if absent, 404 if unknown), `?view=outputs|transcript` picks the view (default `pick_view`: Transcript until something is requested or received), and per-output version and compare params (`<slug>`, `cmp-<slug>`) are kept. `/transcripts/{id}` is a 303 redirect that keeps those params. The `/transcripts/{id}/...` POST and JSON routes stay. The page is the client name, the call selector (older arrow, native `select[data-nav-select]`, newer arrow, "N of M"), the status and Edit title (the selected option already shows the title), the Outputs or Transcript switch, then the view. Transcript view: scrubbed text with a quiet key on the heading row, the output checklist, directions, Copy for Claude (kept inside `data-copy-box`), then Scrub this, so the main action shows on the first screen at 1440x900. Each output has one Copy button and quiet text actions for Copy with placeholders and Edit. The text boxes use a viewport-height clamp from 1200px up so "Ask Claude to change this" shows at 1440x900. Sidebar rows are name, then the ID in small muted text with ellipsis. Outputs view: a board of exactly 3 columns in the `app/outputs.py` order (`output_blocks` always returns 3), the paste box posting to `/clients/{id}/import` with a hidden `tx_id`, and a closed Request more outputs section. A copy then navigates to Outputs. Scrubbing options, running summary, Message and Manage client are under More. `/clients/{id}/import` and `/clients/{id}/outgoing` stay as routes. Tests match markup such as `<pre class="text" id="out-rehydrated-<slug>">`, the "Ask Claude for" legend, `Waiting for Claude` and `Scrubbing options`, so keep those.
- Scrub this: `POST /transcripts/{id}/hide` (CSRF form) calls `wf.hide_in_transcript`, which in one transaction adds the value to the registry and replaces whole-word matches in the transcript, then writes a new `edit` version of each output that holds the word. It refuses overlap with a placeholder, empty text and text over `MAX_HIDE`. The audit log holds IDs and byte counts only. There is no undo.
- Per-place review: Choose each place posts `d{i}=each` and `p{i}_{j}` radios. `parse_review_form` turns each into a decision with `each: True` and a span, `plan_decisions` and `place_ok` check spans against the cleaned text (offset drift), and `scrub_transcript(exact=, skip=)` hides or keeps exactly those spans. A word kept this way is not flagged or propagated. A hidden-here word is a local registry entity (`Entity.local`, `add_local_person`): it rehydrates but is never matched in new text.
- Titles and directions: a transcript title is stored in `client.json` as an optional string (`app/check.py` validates it), as typed (`wf.clean_title` only tidies spaces and invisible characters and limits it to 120). It has no scrubbing and no flagged-word confirm, is shown on screen only and is never part of any text sent to Claude. Older titles that hold placeholders show as stored. Directions are scrubbed like a change request and `DirectionsFlagged` gives a 409 with `flags`. Copy order is intro, ticked instructions, directions, header line, transcript, and the directions are saved as a comment message linked to the call. In change requests and directions only (`plain_requests`), a sentence-opening word from `REQUEST_OPENERS` is not flagged. Mid-sentence capitals still are.
- Summary import strips any header line from the summary (`strip_header_lines`).
- Change request: `POST /transcripts/{id}/outputs/{slug}/request-change` (JSON `text`, `version`, `confirm` as a list of flagged words) scrubs the typed text with `wf.prepare_change_request`, which uses `scrub_message` and the same flag groups as the outgoing route. Parts in order: what to do, the output's instructions, header line, scrubbed request, the chosen version with placeholders, the scrubbed transcript. Output text that leaves as placeholder text (this body, the raw copy target `out-raw-<slug>`, the edit form's starting text) always goes through `wf.placeholder_text`, which masks known real values with the import masking for any version and never rewrites the stored file. Scrub this masks only the latest version, so this is what protects older ones. Flagged words give 409 until every one is in `confirm`, and nothing is stored on a 400 or 409. Success stores a `correction` message and saves the registry in one transaction.
- Typed text: the polling reload and the reload after a copy in `app.js` are skipped while any `textarea[data-keep]` (change, directions or paste boxes) holds text (`hasTyped()`), and a "New version available" note shows instead. The call selector and arrows ask with `confirm` before navigating when text is typed. Links with `data-leave-guard` ask before leaving.
- Test clients: `scripts/seed_test_cases.py` (`seed(store)`) adds 14 synthetic `Test*` clients (Testk to Testn are the newer ones with titles: 9 versions, 40 calls, a name to hide, and an empty client for `samples/review_may.txt`). It skips a first name that exists and honours `MATTER_WORKBENCH_HOME`. It is a dev tool and is not in the zip. Never run it against the real data folder unless the owner asks. Use `--data-dir` or `MATTER_WORKBENCH_HOME` with a folder ending in `.noindex` to try the UI. `tests/test_workspace.py` covers the client page, hide, titles, directions and per-place review.
- Web: no inline script or style, no remote assets, no network libraries (tests enforce it). Every POST route goes through the CSRF guard. New templates must not use `|safe` or inline handlers.
- Storage is files, in `app/store.py`. Each client folder has `client.json` and `transcripts/<tx>/` holding `transcript.txt` and one JSON file per output (`clio-note.json`, `jordan-calendar-overview.json`, `clio-form-note.json`). It never accepts original transcripts or rehydrated text. Real values are plain text in `client.json`, by the owner's decision. Never read a real `client.json`, or send it to Claude, because it holds real names. Use `python -m app.check`, whose report holds no stored values. Tests use temp folders, never the real data folder.
- Save order: new transcript files, then one rename of `client.json`, then replaced text and output files. All writes go through `Store.transaction` under one global lock. One transaction changes one client. Output files are add-only, and a save touches only the outputs it names.
- The data folder must not be inside OneDrive, iCloud Drive, Dropbox or a Git repository (`app/paths.py` refuses). Use `MATTER_WORKBENCH_HOME` to point elsewhere.
- Outputs: the three outputs (slug and display name) are defined once, in `app/outputs.py`. The store takes a required, validated slug for `add_output` and `list_outputs`, and sources are import, mcp and edit. Copy for Claude needs at least one output ticked (the browser and the server both enforce it), stores the choice as `requested_outputs` in `client.json`, and puts only the ticked outputs' instructions above the header line. Instructions are editable in Settings (`instructions.<slug>` in `settings.json`). Import splits `[OUTPUT: slug]` sections and saves them in one transaction, and an unknown slug blocks the save. The connector's `save_output` takes the slug and never splits markers. Hand edits work on placeholder text, are masked like an import and save as new versions. Jordan is staff, so the name is not scrubbed in instructions.
- UX round 2: output source `hide` (label "Name hidden", validated by `check.py`, shown in export). Transcript meta also holds `planned_outputs`, `directions` and `directions_ok`; `Entity.office` is stored only when true. `workflow.known_names` builds a cross-client index so `detect_client` ignores staff and shared names, ranks on the non-office speaker, and `save_transcript` marks the office speaker. `REQUEST_WORDS` in `pipeline.py` lists plain words not flagged in change requests and directions. New routes: `POST /transcripts/{id}/scrub-preview`, `POST /transcripts/{id}/hide-word`, `POST /clients/{id}/registry` action `save`, and settings sections (`section=model|connector`, JSON save in place). The selector label is title first with no ID; the ID stays in `data-id`. User text says "hidden name", never "placeholder" or "registry". `tests/test_ux_round.py` covers this round.
- UX round 3: a name hidden for one transcript only (`Entity.local`, from Choose each place) is found by `wf.local_names(registry, scrubbed_text)`: local entities whose code the transcript text holds. Text typed for Claude about that transcript (change request, directions, Message) is scrubbed with `local=` (`pipeline.local_matches`, whole word, case-sensitive, wins over the model, hidden even with keep-first-names), so it is replaced by that code and never flagged; the stored copy holds the code and `directions_for_display` shows the real word in the box. The Hide beside a flagged word (`POST /transcripts/{id}/hide-word`, `wf.hide_for_request`) only adds the value to the client's hidden names: it never rewrites transcript.txt, makes no output version, and the box keeps the typed words (the script re-checks, it does not insert codes). Rewriting a transcript is only the Scrub this form. The change request sends `latest`; `StaleVersion` gives 409 `stale` if the output has a newer version. The review directions box checks live through `POST /clients/{cid}/intake/directions-preview` (it posts the whole review form, so Choose each place choices count) and Hide there adds a `dir_hide` hidden input that `save_transcript(hide=)` adds to the registry after the transcript is scrubbed. Hidden names rows say "Only in <title or date>" and Merge options show the code. "Ask Claude for this" moves saved directions to "Last sent" with Use again. Import check says "Belongs to <title>, <date>" or "Summary for <client>" and strips the header from the preview. `ScrubResult.info` carries the plain "Read N speaker lines (Name: text)." note. The transcript filter shows "Choose one of N matches" when the open call is filtered out. The connector checkbox saves on change. `tests/test_round3.py` covers this round.
- UX round 2, second pass: a placeholder code (`PLACEHOLDER_RE` in `app/scrub/registry.py`, `has_token`, `token_spans`) is never a name. Registry writes raise `PlaceholderValue`, `_scrub` and `mask_known_values` ignore anything overlapping a code, and `iter_forms` skips stored code values. Directions are stored scrubbed, shown through `wf.directions_for_display`, and kept after a copy (`copy_for_claude` saves them again). `python -m app.check --fix` (`check.fix`) removes hidden-name entries that hold a code and prints counts only. `copy_intro` and `change_intro` mention `save_output` only when `Settings.mcp_enabled`. `ImportCheck.replaced` is for the check page and is never stored. `parse_lenient` also reads "Name: text" lines with distinct labels as speakers (rule in README). `tests/test_round2.py` covers this round.
- UX round 4: scope rule for typed text. `Entity.only` (transcript ids) and `via` (transcript that added it) mark a transcript-only entry; `wf.local_scope` returns (auto, ask) for a local word, auto when every place was scrubbed and ask when the word still appears as plain text. `wf.scrub_typed` and `pipeline._scrub(ask=)` flag ask places with a `Flag.code`; the client sends `places=[{start, word, choice}]` (validated against the cleaned text by `wf.clean_places`) and a blanket `confirm` never settles ask places. `Store.decided_keep` skips words kept for the transcript unless they match a hidden person. `hide-word` (and `POST /clients/{cid}/outgoing/hide-word`) is transcript-only by default and client-wide only with `client`, via `registry.make_client_wide`. The Hidden names delete notice is a session flash in `app.state.flash`, never in the URL. The change text survives a stale refusal through sessionStorage key `change-<tx>-<slug>`. The selection popup uses `snapWords` and `selectedHideText` in `app.js`. Tests are in `tests/test_round4.py`.
- Round 5: the Transcript tab shows real values (`wf.real_segments`, tagged unless the type is switched off or first names are kept). Scrubbing options sit in `_options_row.html` under the transcript and on the intake page, post to `/clients/{id}/options` with `tx` and `back`, and apply at copy time through `wf.restore_switched_off` in `copy_for_claude` and `prepare_change_request`. The copy record stores the hidden form. `Store.delete_transcript` and `Store.delete_client` plus `wf.delete_transcript` (which also drops call-only names no other call uses) are behind confirm pages at `GET /clients/{id}/delete` and `GET /transcripts/{id}/delete`. `wf.project_instructions(connector_on)` feeds the Settings section "Instructions to save in Claude". Tests are in `tests/test_round5.py`; `Session.stored_text(tx)` reads the saved text because pages now show real values.
- Round 5b: name options are First names and Last names (client settings `first_names`, `last_names`; Names in the page is derived and has no setting; both unticked removes PERSON from `types`). The first name is the first word and the last name is everything after it. `wf.person_pieces` splits a name code into hidden and visible pieces for `restore_switched_off` (copy and change request) and `real_segments` (Transcript tab). Part `rest` (everything after the first word) is added to `PLACEHOLDER_RE` and resolved by `Registry.surface`, so nothing saved changes. `wf.keep_flags` gives the per-client keep values to `check_import`, `edit_output`, `view_output` and `placeholder_text`, so masking and the plain-name warning follow the options. Typed boxes still hide last names. The row is synced in `app.js` (`data-name-all`, `data-name-part`).
